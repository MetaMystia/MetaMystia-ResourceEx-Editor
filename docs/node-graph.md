# 节点图

入口：打开资源包后，选择“场景与节点 → 节点图”。节点图是任务节点（`missionNodes`）和事件节点（`eventNodes`）的另一种视图，与“任务节点”“事件节点”页面编辑同一份数据；原有的列表与表单页面保持不变。

## 界面

宽屏时编辑器占满导航栏以下的窗口，窄屏时画布在上、属性面板在下。

| 区域     | 内容                                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------- |
| 画布左上 | 新建任务、新建事件；“定位节点”按任务、事件、羁绊入口、外部节点分组                                                          |
| 画布左下 | 缩小、适应（显示全部节点）、放大、自动排列                                                                                  |
| 画布右下 | 缩略图，可拖动和缩放（窄屏隐藏）                                                                                            |
| 右侧面板 | 未选择时为说明和图例；选择节点后显示“连接”（来自/去往，可点击跳转）和原有的任务或事件编辑表单；选择连线后显示两端和删除按钮 |

点击卡片或在卡片获得焦点时按 Enter/空格选择，点击空白处取消选择。选择后整条上下游链路保持高亮，其他节点淡化。Delete 键不会删除节点，删除仍走表单里带确认的按钮。

## 拖拽连线

从卡片右侧的出口按住拖到另一张卡片（落在入口点或卡片上都可以）即追加一条引用，写入的字段与表单相同：

| 从                   | 拖到                                     | 写入                                                  |
| -------------------- | ---------------------------------------- | ----------------------------------------------------- |
| 任务或事件的“结算时” | 事件（含外部事件）                       | 来源的 `postEvents`                                   |
| 任务或事件的“演出后” | 任务（含外部任务）                       | 来源的 `postMissionsAfterPerformance`                 |
| 事件的“结算时”       | 任务“完成指定数量的事件”条件那一行的入口 | 该条件的 `events`（`text` 留空）                      |
| 羁绊入口的某一等级   | 事件                                     | 角色 `kizuna.lvNUpgradePrerequisiteEvent`（替换原值） |

不符合上表、连到自己或已经存在的连线会被拒绝，入口点只在可连接时高亮。拖到空白处松手会在该位置新建节点并连好：“结算时”和羁绊等级新建事件，“演出后”新建任务；从羁绊等级新建的事件默认名为“角色名羁绊 LVN 前置”，触发器为“羁绊等级升级时”并指向该角色。

点击连线（或聚焦后按 Enter）选中它，连线中点和右侧面板都会出现“删除连线”，删除对应的那一项引用；羁绊前置事件删除后该等级字段变为空。外部信号连线来自“发送任务完成信号”奖励，只能在表单里修改。编辑器没有撤销，删除连线不会删除节点。

拖线靠近画布边缘时视图会自动平移；端点只在约 10 像素内吸附，落在卡片上时按光标下的卡片连接。

## 视图

节点很多、整体缩放后看不清时，打开页面和“自动排列”会从左上角按 80% 缩放显示流程起点；“适应”始终显示全部节点。

## 卡片与连线

卡片左侧是“被安排/开始”入口，右侧是两个出口，对应游戏 `RunTimeScheduler` 完成节点的两个阶段：

1. 结算（`FinishSchedulerNode`）：发放 `rewards`，安排 `postEvents`，开始 `postMissions`。
2. 演出（事件的 `eventData` 或任务的 `missionFinishEvent`）结束后（`FinishSchedulerNodePost`）：发放 `postRewards`，开始 `postMissionsAfterPerformance`。

| 连线                 | 数据                                                                    | 画法                           |
| -------------------- | ----------------------------------------------------------------------- | ------------------------------ |
| 安排事件（结算时）   | 任务或事件的 `postEvents`                                               | 橙色实线，从“结算时”出口       |
| 开始任务（演出后）   | 任务或事件的 `postMissionsAfterPerformance`                             | 蓝色实线，从“演出后”出口       |
| 任务条件等待事件完成 | 任务条件 `CompleteSpecifiedFollowingEvents.events`                      | 灰色虚线，连到该条件那一行     |
| 发送外部信号         | `FinishFakeMission` 奖励的 `rewardId` 匹配任务 `FakeMission` 条件的标签 | 紫色点线，连到该条件那一行     |
| 羁绊前置事件         | 角色 `kizuna.lvNUpgradePrerequisiteEvent`                               | 绿色虚线，从“羁绊入口”对应等级 |

启用了羁绊的角色都有一张“羁绊入口”卡片，每个等级一行（Lv1→2 至 Lv4→5），未设置前置事件的等级显示为灰色。对话包、角色只显示在卡片上，不画成节点。引用了本资源包里不存在的节点时显示虚线卡片：带本包前缀的是“缺失”（导出校验会报错），其他是“外部”（原版或其他资源包）。

“未找到入口”表示从任何羁绊入口沿“安排事件/开始任务”都到不了这个节点。ResourceEx 目前自动安排的只有羁绊前置事件，但节点仍可能由原版或其他资源包的节点安排，所以只作提示。

图的结构由 `app/domain/resourcePack/schedulerGraph.ts` 从 `collectResourcePackReferenceLocations` 推导，不另存数据。

## 布局

默认用 dagre 从左到右分层排列。第一次拖动节点后，当前所有节点的位置都会固定下来；之后新出现的节点放在已摆好的前驱右侧，没有前驱时放在所有节点下方。改标签时位置跟着节点走。“自动排列”清除手动位置。

节点位置保存在本浏览器（`nodeGraphEditor:positions`，按工作区区分，保留最近 20 个工作区），不写入工作区文档、`ResourceEx.json` 或导出的 ZIP。换浏览器、清除站点数据或重新导入后回到自动排列。

## 后续计划

- 文文新闻节点（游戏 `NewsNode`，`SchedulerNode.NodeType.Aya`）：作为第三种节点，由 `ScheduleNews`（带天数）与 `DismissNews` 奖励连接。需要 Mod 先支持。
- 逆向代码中已有、ResourceEx 尚未提供的字段，Mod 支持后可在图上增加：`postMissions`（结算时开始任务）、`preNodes`（前置节点全部完成才能安排，否则请求直接丢弃且不会补发）、`eventLockMode`（事件锁）、`scheduleAtFirst`/`executeOrder`、`scheduleOnce`、`autoCompleteAtDayEnd`、`loopedMission`，以及 `CancelEvent`、`FinishEvent`、`ForceCompleteMission`、`SetTargetMissionFulfilled` 这类控制其他节点的奖励。
